# 悬停看板（迷你条）五口径改版 + 黑板同步换词

## 可探测性结论（先回答「都能探测到吗」）

| 指标 | 可探测性 | 来源 |
|---|---|---|
| ③ 全文（请求输入） | ✅ 真值 | `usage.inputTokens + cacheReadTokens` 逐请求累加 |
| ④ 缓存命中数值 | ✅ 真值 | `usage.cacheReadTokens` |
| ⑤ 缓存命中率 | ✅ 真值（派生） | `cacheRead ÷ (input+cacheRead)`，分母 0 时记 0 |
| ② 产出输出 | ✅ 真值 | `usage.outputTokens` |
| ① 用户输入 | ⚠️ 只能估算 | provider 不单独上报用户侧；对 `user/message` 事件文本跑启发式计数（CJK 逐字 + ASCII 按词，与宿主截断用的 estimateTokens 同款），展示带「(估)」标注（F71 诚实标注纪律） |

## 新文案（用户定的五个名词）

**迷你条（悬停玲娜贝儿）**：
```
[═══节奏表盘═══] 高强度          ← 现有，保留
今日 请求输入 619.9万 · 命中 85.7%     ← ③+⑤
缓存命中 531.5万 · 产出 7.8万          ← ④+②
你的输入 ~0.9万(估)                    ← ①
1 等审批 · 1 运行 · 1 完成             ← 现有状态行
本会话 请求 12.3万 · <会话名>          ← 本会话简化为请求口径单值
```

**黑板 tokens 行同步换词**（消除「入/出/缓存读」的旧口径歧义）：
```
今日 请求输入 619.9万（缓存命中 531.5万 · 85.7%）· 产出 7.8万 · 你的输入 ~0.9万(估)
```

## 改动清单（一个 commit）

1. **`src/dashboard.js`**（纯函数 + 测试）：
   - 移植 `blocksText`（text 块提取）与 `estimateTokens`（CJK 逐字/ASCII 按词）为导出函数
   - 新增 `estimateUserTokensByDay(events)`：扫 `user/message`，按日累加估算值
   - 新增 `hitRate({inputTokens, cacheReadTokens})`：0-1 小数，分母 0 → 0
   - `summarize` 的 `tokensText` 改用新名词（含命中率与用户输入估算，签名加 `userEst` 参数）
   - 测试：estimateTokens 中英混合/空串、userTokens 按日分桶、hitRate 零分母、tokensText 名词断言
2. **`src/index.js`**（宿主聚合）：
   - `dashState.usage` 扩展派生字段：`requestTotal`、`cacheHitRate`、`userEst`（今日）；`session` 侧同样加 `requestTotal`（本会话请求单值）
   - `estimateUserTokensByDay` 复用既有的每会话事件数组（`sessionEventsCache`），零额外采集
3. **`src/client.js`**：
   - `MiniBar` 按上面行结构重排（表盘/三数据行/状态行/本会话行），命中率渲染 `(r*100).toFixed(1)+'%'`，「(估)」后缀
   - `Board` 无需改（tokensText 宿主已拼好）
4. 三绿（25+ 用例）→ 提交推送，PR 自动更新；浏览器刷新即生效（纯客户端+快照字段，服务需重启一次让宿主半出新字段——link 安装下重启 `pnpm dsh web` 即可）。

## 不做

不改 `/state` 既有四桶字段名（向后兼容，只增派生字段）；不加金额换算（纯 token 口径不变）；不动画集/交互（6.6 规则不动）。
