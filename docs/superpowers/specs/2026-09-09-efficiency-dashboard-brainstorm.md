## 1. 背景与定位（继承 issue #3，不可动摇）

- 本插件是**效率工具**：桌宠是 agent 工作状态的**低打扰表达层**，不做养成、不做经济、不做任何制造回访义务的游戏化系统。
- 每个提醒都必须**可行动**：提示了用户能据此做点什么（收尾会话、处理审批、换个思路）。
- 成本口径：**纯 token，不折算钱**（不维护价目表）。
- 宠物上不承载操作按钮（守「纯展示」定位），唯一的动作增强是**导航直达**。

## 2. 调研综述（四路来源，2026-09 实测）

| 调研路 | 代表对象 | 对本设计最有价值的发现 |
|---|---|---|
| LLM/Agent 用量监控 | ccusage、Claude-Code-Usage-Monitor（8.7k★）、菜单栏工具群、Langfuse、AgentOps、LiteLLM | 三级颜色阈值+「何时耗尽」预测是核心卖点；重置倒计时比百分比更有行动价值；反面教训：固定阈值不可调→告警疲劳 |
| 桌宠/助手软件 | VPet、vscode-pets、Clippy、workbuddy-buddy、openpets、awesome-codex-pet | 2024-2026 已出现成熟范式：7 状态机+渐进摸鱼动画+宠物即审批门+白名单隐私；Clippy 证明「不请自来的打断」必死 |
| 系统监控/氛围计算 | RunCat、Ambient Orb、Uptime Kuma、CCMenu、灵动岛 Live Activity、calm technology 八原则 | 主编码通道=「速度/步态+颜色+姿态」三通道冗余，文字只在展开层；打扰预算制：稳态零动画，跃迁才播一次 |
| 编码 agent 状态 UI + 告警设计 | Claude Code/Cline/Roo/Codex CLI、WakaTime、Grafana 告警、AWS Budgets、Apple HIG | 常驻可见的成本计数（不要求用户主动查）；告警分级/合并/静默/可行动是成熟学科 |

**贯穿性结论**：功能可以无穷多，但「宠物=效率看板」的形态共识非常集中——**常驻低打扰位 + 形态编码（不用文字）+ 达阈值才出声 + 每条提醒可行动**。这四条成为第 7 章实现约束的来源。

## 4. 筛选记录（五轮）

**轮 1（轴默认 + 大表）**：信息范围=仅 dsh 会话数据；成本口径=纯 token；交互边界=纯展示+直达；常驻信息=悬停/点开两档。
**轮 2（用户逐条意见）**：否决 F04/F07/F11/F12/F16（价格类）、F20/F21（预测式）、F23（分类够用）、F33（监控不必那么细）、F34（dsh 自带）、F39（复杂）、F62（映射够用）、F80（审批机制复杂）；纪律类定性为「优化性内容，可做但非核心」→ 压缩为实现约束。
**轮 3（重叠归并确认）**：悬停迷你条 ✅、审批纯直达 ✅、roll-call 记二期（不调 LLM）✅、年龄标注 ✅、F56 与 F23 同族一并存档 ✅。
**轮 4（形态细化）**：F05 按模型分布进一期（dsh 本就多模型多供应商）；F15 单会话阈值否决（无上限概念，仅保留日级）；速度编码否决（精灵帧数少，变速会卡顿/鬼畜）→ 改「节奏表盘」并入悬停迷你条；F63/F64/F65/F66/F67 打扰治理类全部否决（卡片不合并/关宠即勿扰/无必要性）；F74 确认 v2 已覆盖（codex 导入）；F81 维持存档（附变体想法）；③链条简化（L2 姿态升级取消，理由见 6.3）；④黑板改「完成事件→限时总结入口→点击展开」；⑤补信息形式谱系与卡片冻结原则。
**轮 5（一致性排查 + 交互树）**：修复 8 处冲突——点击红卡双重语义统一为智能跳转；阈值提醒去气泡（数字归举牌）；迷你条去内嵌点击（纯读取）并补「本会话=最近有事件会话」定义；F60 提前一期（迷你条状态行即 roll-call 本体）；黑板补 ✕/点外部关闭；TTS 三优先级定死（语音组>TTS>静默）；谱系表补第 10 种（总结限时入口）；新增 6.6 交互类型树与行为一一映射。
**轮 6（交互模型完备性审计）**：补 3 个真实缺口——ESC 逐层关闭浮层、滚轮穿透/面板内滚动规则、右键响应范围仅宠物本体；显式预留 3 个接口（键盘快捷键、拖放文件导入、长悬停深读档）；写明 4 扇有意关上的门与未来接入的三条正道；明示「本会话=最近有事件会话」焦点语义。

| 同族组 | 成员 | 重叠本质 |
|---|---|---|
| 时间姿态族 | A3 高强度、A5 长任务、F29 摸鱼 | 同一把「事件时间轴→姿态」连续分阶尺的三个刻度 |
| Token 表现族 | A1 阈值、B3 里程碑、悬停迷你条 | 同读一个计数器（会话/日级三分账），被动喊/被动报/主动查三个面 |
| 审批升级族 | A4 滞留、F55 标题闪烁、审批直达、F58/F60 会话一览 | 同一条按等待时长逐级升压的召集链的不同环节 |

由同族关系 + 剩余独立点，归纳出 5 类核心需求（每类一句话）：

| # | 核心需求 | 吸收的功能点 | 组件 |
|---|---|---|---|
| ① | 不用切窗口就知道每个 agent 处在什么节奏 | F28、F27、F29 | 时长姿态引擎 |
| ② | token 烧到哪了——想查有处查，越线有分寸地喊 | F05、F13/F14、F37、F52/F53 | Token 计量器 |
| ③ | 需要我的地方别让我错过（尤其人不在页内时），一步直达 | F26/F55、F82、F58/F60 | 审批召集链 |
| ④ | 干完活有个交代 | F35/F36、F01、F08、F31、F06 | 小黑板 |
| ⑤ | 同样的信息用合适的容器和通道呈现 | F61、F57、F54、F83 | 表达容器 |

①②③是数据引擎（宿主半），④⑤是呈现层（客户端半）——与 v2.0.0 的胖宿主+薄客户端架构同构。

一图读懂：**宠物本体动画变体承载①，悬停迷你条（含节奏表盘）是②③的主动查询面，头顶卡区（已有，冻结）叠加③的直达与⑤的年龄标注，左右浮窗是④②的明细层，字幕格是⑤的短文本层，标签页标题是③的页外召集信号。** 新增的常驻 UI 元素数量：**零**（迷你条仅悬停期间存在）。浮窗互让规则：黑板（事件触发）与迷你条（悬停触发）不会同时出现；万一同时，黑板优先、迷你条避让至另一侧。

### 6.1 需求①：知道每个 agent 处在什么节奏 → 时长姿态引擎

- **组合**：F28 高强度 + F27 长任务 + F29 摸鱼阶梯——三个功能点是同一把尺子的三个区间。
- **方案选择**：
  - A. 独立 UI 元素（计时条/仪表贴宠物旁）——否：新增视觉占用，文字化，违反「不必说话也能沟通」。
  - B. 三个独立提醒功能（各弹各的气泡）——否：三次打扰、三份重复逻辑，正是用户批评的「多而杂」。
  - C. **连续姿态分阶尺（选定）**：一个引擎把「事件密度 × 距上次事件时长 × turn 开合」映射到宠物姿态**变体**，宠物动画本身就是显示层。
- **选 C 的理由**：calm technology 原则「信息先进余光」「不必说话也能沟通」；零新增 UI 元素，完全复用宠物本体；实现上是一个函数（时间轴→档位），不是三个功能。
- **明确不做速度调制（轮 4 用户裁决）**：RunCat 式「动画速度=负载」需要专门绘制的多帧动画，现有精灵帧数少——放慢会卡顿、加快会鬼畜。因此**档位表达一律为切换动画变体，绝不改变播放帧率**；「强度/速度」这个维度由悬停迷你条中的**节奏表盘**承担（见 6.2，静态读数，非持续动画）。
- **设计**：
  - 档位刻度（默认值，全部进设置卡可调）：
    | 档位 | 判定（初始值） | 姿态 |
    |---|---|---|
    | 高强度 | 近 5 分钟事件数 ≥ N | 狂奔/擦汗变体（换变体，不变速） |
    | 活跃 | turn 开着，正常事件流 | 现有 running 姿态 |
    | 长跑 | turn 开着 + 静默 ≥ 3 分钟 | 看表姿态（防挂机干等） |
    | 空闲 | turn 关着 + 静默 < 15 分钟 | 现有 idle/环视 |
    | 摸鱼 | turn 关着 + 静默 ≥ 15/25/35/60 分钟（四阶） | 渐进咸鱼变体 |
  - 任何新事件立即重置到活跃/空闲；档位跃迁只播一次短动画（纪律 F50）。
  - 数据全部来自已有事件时间戳，无新采集。

### 6.2 需求②：token 烧到哪了 → Token 计量器（一个数据核 + 三个表现面）

- **组合**：F13/F14/F15 阈值 + F37 里程碑 + F52/F53 悬停迷你条（二期 F02/F43/F10 挂同一数据核）。
- **方案选择**：
  - A. 常驻 HUD 数字条——否：违反载体约束（区域零遮挡），高频跳动数字是 TrafficMonitor 式反面模式。
  - B. 全部主动查询（点开才看）——否：越线了用户不知道，失去警报价值。
  - C. **一个计数器 + 三表现面（选定）**：主动查（悬停迷你条）/ 被动喊（阈值举牌）/ 周期报（黑板一行）。
- **选 C 的理由**：这是 ClaudeUsageBar/ccusage 等菜单栏工具群的共识设计（常驻低打扰位+达阈值才出声）；三功能点同读一份数据，分开做=三份重复实现；B3 里程碑本质是「一次性整数关口阈值」，并入阈值规则后少一个功能点。
- **设计**：
  - 数据核（宿主半）：**会话级+日级计数（展示口径），阈值仅设日级**（单会话上限概念已否决，F15 存档），输入/输出/缓存三分账 + 按模型/供应商维度拆分（F05，事件是否带模型维度待 plan 验证），随 `/state` 快照下发（token 数据源在 plan 阶段验证，见附录 A）。
  - 表现面 1·悬停迷你条（主路径，0 次点击）：悬停宠物 ≈0.5s 浮现于宠物侧方，内容 = **节奏表盘**（指针/弧线指示①当前档位：狂奔→活跃→看表→空闲→咸鱼，静态读数非持续动画）+ 数据行「今日 12.3万 · 本会话 2.1万」（**本会话 = 最近有事件的会话**）+ 状态行「1 等审批 / 1 运行 / 1 完成」（= F60 roll-call 的一期形态，纯拼接）。多模型时**只读并列**显示各模型占比（迷你条内无任何可点元素——「悬停=纯读取」铁律）。移开即消失；存在期间不拦截区域外点击。
  - 表现面 1b·右键菜单「今日用量」（次路径，1 次点击）：打开**同一个迷你条容器**（手动模式，点击外部关闭）——两个触发方式、一个容器，不产生第二组件。**交互规范（轮 4 用户要求）：查看 token 数据总操作 ≤1 次点击。**
  - 表现面 2·阈值举牌（被动喊）：仅**日级**阈值，数值与档位全可配（默认关）；分 2-3 档阶梯（如 80%/100%）递进提醒——F14=数值可配（避免硬编码被骂的社区教训），F13=分档递进（避免「只响一次就再也不管」）；触发时宠物**举牌「今日已消耗 X」+可选语音**（不叠加字幕气泡——容器分工：数字归举牌，一句话归气泡，见 6.5）；**同一档只报一次**，不重复轰炸；档位完成使命后回稳态。
  - 表现面 3·里程碑：累计 token 过整数关口（100 万/500 万…）一句话气泡，一次性、不持久化、不成系统。

### 6.3 需求③：需要我时别让我错过（尤其人不在页内时）→ 审批召集链

- **组合**：F26/F55 标题闪烁（含超时触发）+ F82 直达 + F58 会话清单（二期 F60 并入会话一览）。
- **与颜色系统的区分度（轮 4 用户质询的正面回答）**：现有红/黄/绿/深红是**状态分类**（agent 处在什么状态），它不承载**时间维度**——一张红卡挂 30 秒和挂 30 分钟颜色完全一样；也不覆盖**页外场景**——用户切去别的标签页后，WebUI 内的一切（红卡/语音/姿态）都不可见。本组件补的正是颜色系统不承载的两个维度：**超时（时间）+ 页外（空间）**。相关性高的部分（页内红卡、审批语音、卡片按 error>approval>running>done 排序——排序 v1.3.0 已有）全部沿用现状，不做任何重复。
- **方案演化**：原设计为 L0-L3 四级升压链 → 用户裁决「L2 姿态升级与红卡信息冗余，区分度不足」→ **简化为仅两件新增**：
  1. **标题闪烁（页外召集）**：审批等待 ≥ N 分钟（默认 5，可配可关）**且页面不可见**（document.visibilityState ≠ visible）时，document.title 轮换「🦊 审批等待中…」；`approval/decided` 或用户回到页面即恢复原标题。
  2. **审批直达（末端动作，轮 5 统一表述）**：点击状态卡的唯一行为 = **智能跳转**——该会话有待审批 → 直达审批锚点；否则 → 跳转会话+标已读（现有行为）。这是现有点击行为的超集而非并行第二行为（v2.0.0 FR-6 的「点击行为不变」适用于 v2 阶段；v2.1 起升级为智能跳转）。
- **选简化方案的理由**：页内场景已被现有红卡+语音+排序完整覆盖（再加等级=重复信息，用户裁决正确）；页外场景只有标签页标题这一个通道可达（whale-on-desk 验证过）；直达是零新增 UI 的行动闭环。
- **会话一览**：右键菜单子菜单（会话名+状态色点+点击直达）；二期加一句话形态（F60，纯拼接零 LLM）。

### 6.4 需求④：干完活有个交代 → 小黑板

- **组合**：F35 指标 + F36 时机（二期 F38 周报/F45 导出/F44/F41/F42/F09 全为本组件参数扩展）。
- **方案选择**：
  - A. 常驻侧栏图表面板——否：宠物不做常驻面板，Grafana 全家桶对个人是重型方案。
  - B. 逐条推送总结消息——否：打扰且不可回看。
  - C. **临时浮窗黑板（选定）**：出现 → 停留 → 自动消失，可手动唤回最近一期。
- **选 C 的理由**：issue #3 载体约束原文已定（左右浮窗、不占卡区、不挡点击、临时性）；TRMNL/e-ink 低频快照证明静态排版足以承担复盘；WakaTime 验证周期复盘的真实价值在「汇总」而非「实时」。
- **设计**：
  - 位置：宠物左侧或右侧（自动避让：优先与迷你条相反一侧）；未显示时该区域完全无遮挡（无透明蒙版占位）。
  - 一期指标集：会话数 / turn 数 / token 三分账（会话与日级）/ 工具调用 Top3（次数+耗时）/ 最长单 turn / 报错次数。
  - 触发（轮 4 用户提供的设计）：**任务完成事件 → 宠物旁限时出现轻量「📖 总结」入口（默认 15s，可配 10/15/20s）→ 点击一下黑板浮现；错过即过期消失，不打扰、不追问**。
  - 辅触发：关闭/隐藏桌宠时直接分发一次（issue#3 B2 的关宠分发项保留）。
  - 唤回：右键菜单「查看最近总结」随时手动唤回最近一期。
  - 已删除：每小时/每日日终定时自动弹（B2 定时项取消——遵循「错过就算了」的精神，不做制造存在感的推送）。
  - 行为：黑板展开后自动消失（默认 15s 可配）；黑板右上角 **✕ 手动关闭**；点击黑板外部空白同样关闭（与 ✕ 等价）。
  - 二期参数化扩展：周期维度（周报）、指标维度（缓存率/失败率/耗时漂移/等待分类/最贵任务）、输出维度（复制文本/导出图片）。

### 6.5 需求⑤：信息用合适的容器呈现 → 表达容器

- **组合**：F61 举牌 + 已有气泡/字幕 + F57 TTS + F54 布局约束 + F83 年龄标注。
- **现状发现（重要）**：v1.3.0 卡片行取材逻辑（`src/index.js:180-186`）**已经是一条「最新动态」回退链**：`assistant 正文 > tool/result 内容 > tool/call「运行 <工具名>」 > user 消息`，取最新 2 行、每行截断 24 字。因此 F23（当前动作展示）与 F56（思考摘要）**已被现状覆盖**，双双存档——这正是「同源功能点合并到单一组件」的最好例证。
- **方案选择**：每个功能自带提示样式（否，样式爆炸行为不一）→ **统一容器协议（选定）**：按内容类型选形态。
- **选它的理由**：VPet MessageBar/vscode-pets 等所有成熟桌宠都是「牌/泡/板」三级容器结构；容器统一后，新功能只生产内容，不发明呈现方式。
- **设计**：
  - **信息形式谱系（轮 4 用户要求的归纳：一二期全部规划共 9 种形式）**：
    | # | 形式 | 状态 | 承载内容 |
    |---|---|---|---|
    | 1 | 头顶状态卡 | 已有，**冻结** | 项目名+最新动态行+状态色点 |
    | 2 | 宠物姿态变体 | 已有 | ①档位（狂奔/看表/咸鱼…，换变体不变速） |
    | 3 | 字幕格台词 | 已有 | 语音台词/一句话 |
    | 4 | 举牌 | 新 | 短数字（阈值/里程碑数值） |
    | 5 | 悬停迷你条+节奏表盘 | 新 | ②③主动查询面 |
    | 6 | 左右浮窗黑板 | 新 | ④明细总结/②阈值详情 |
    | 7 | 标签页标题 | 新 | ③页外召集 |
    | 8 | 右键菜单 | 已有结构+新子项 | 会话一览/今日用量/查看最近总结 |
    | 9 | TTS 语音通道 | 已有语音组扩展 | 可选朗读（优先级：语音组音频 > TTS > 静默） |
    | 10 | 📖 总结限时入口 | 新 | ④黑板的前奏入口（完成事件后 15s 限时） |
  - **卡片冻结原则（轮 4 用户裁定）**：头顶状态卡现有结构（项目名+动态行+色点）保持不动，一切新功能一律走新组件、不向卡片塞内容；唯一例外是已批准的行尾年龄标注（属行内微调，不改结构）。
  - 三形态规则（新增内容的容器选择）：短数字类（≤8 字）→ **举牌**；一句话（台词/里程碑）→ **气泡**（现有）；明细（总结/阈值详情）→ **黑板浮窗**（组件④）。
  - 通道：视觉为主；语音三优先级（轮 5 定死）：**语音组音频 > TTS 朗读 > 静默**——事件播报文本在有对应语音组音频时播音频，无音频且 TTS 开启时用浏览器语音读文本，两者皆无则静默（外部宠物无语音组也能说话的兜底）。
  - 取材链增强（本轮唯二新增之一）：卡片行沿用现有四档回退链，行尾追加灰色年龄标注「×s/×m」（来自事件时间戳，与①同源），解决「运行 bash 挂 5 分钟分不清是刚发生还是卡住」；思考文本兜底列为可选开关（默认关）。
  - 布局纪律（F54）：左右浮窗不占头顶卡区与下方字幕格；未显示时零遮挡；白名单（F72）：只显示静态文本与结构化摘要，不显示 prompt 原文与密钥。

### 6.6 交互类型树与行为一一映射（轮 5 新增）

**第一层：交互语义**（每个交互类型一个语义，全插件统一）：

| 交互类型 | 统一语义 | 铁律 |
|---|---|---|
| 悬停（≈0.5s） | 信息扩展，**纯读取** | 迷你条内一期无任何可点元素 |
| 单击 | 触发一次动作（跳转/展开/关闭/反馈），**每个目标有且仅有一个行为** | 见第二层矩阵 |
| 双击 | 说话（语音组台词+可配置动作） | 现有行为，不变 |
| 右键 | 菜单（导航与设置入口） | 现有结构+新子项，不发明第二菜单 |
| 拖拽（主键按住移动） | **纯物理动画**（方向动画+惯性+重力），无附加动作 | 拖拽期间迷你条隐藏、悬停检测挂起 |
| 无交互（被动展示） | 事件驱动，无需用户参与 | 姿态变体/举牌/台词/黑板自动出现/标题闪烁 |

**第二层：目标 × 单击行为矩阵**（一对一，杜绝「一个行为两个组件」）：

| 点击目标 | 唯一行为 |
|---|---|

**共存与避让规则**（多元素同屏时的仲裁，写死避免代码里隐式优先级）：

1. 黑板（事件层）与迷你条（查询层）原则上不同时出现；同时触发 → **黑板优先**，迷你条延后至黑板消失。
2. 📖 总结入口是时限元素，优先级最高；与迷你条并存时入口置上层、互不遮档。
3. 拖拽期间：迷你条隐藏、悬停检测挂起，松手 0.5s 后恢复。
4. 双击动作临时覆盖①档位动画（瞬时动作 > 任务态，沿用 v2 动画优先级模型），播完回档位。
5. 右键菜单打开期间，其他浮层不响应交互。
6. 标题闪烁不参与页内交互：回到页面即恢复原标题，无需任何点击处理。
7. 滚轮（轮 6 补）：宠物本体与迷你条上**不劫持滚轮**（事件穿透回页面，宠物永远不抢页面滚动）；黑板与右键菜单**内部**正常滚动自身内容。
8. 右键响应范围（轮 6 补）：仅宠物本体右键弹出菜单；状态卡与各浮层的右键无自定义行为。

**第四层：完整交互类型清单与预留接口（轮 6 新增）**——全空间盘点，每类标注现状或预留位：

| 交互类型 | 语义/归属 | 状态 |
|---|---|---|
| 悬停短（≈0.5s） | 纯读取（迷你条） | 一期 |

| 单击 | 每目标唯一行为 | 一期 |
| 双击 | 说话 | 已有 |
| 三击 | — | 永不启用（与单击/双击的时序判定冲突，自找歧义） |
| 右键 | 菜单（仅宠物本体，见规则 8） | 一期 |
| 拖拽（按住宠物移动） | 纯物理动画，**不承载任何命令**（拖到边缘隐藏、拖到卡片跳转之类一律不做） | 已有；**门有意关上** |
| 拖放文件到宠物（HTML5 drop 事件，与上面的拖拽物理是两套事件互不相干） | 预留：外部宠物 zip 拖放导入快捷入口（v2 导入体系的自然扩展位） | **预留接口**（v2.1+ 可选启用） |

**关门声明**：拖拽不承载命令、迷你条纯只读、单击每目标单行为、宠物本体无操作按钮——这四扇门是**有意关上的**（防功能蠕变与语义漂移，均为用户裁决）。未来新增交互只允许从三处接入：① 右键菜单新子项；② 上表预留接口；③ 新浮层组件并在第二层矩阵补一行。不得复用已关门的通道。
