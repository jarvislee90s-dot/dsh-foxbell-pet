## R0 总体：用量看板板块（一个数据核、三级披露）

**来源背景**：设计稿 §9 二期清单中 F05（模型分布）、F10/F40（趋势/周对比）、F38（周报）三件事需求重叠度极高——读同一份聚合数据（会话事件的 usage 按日/按路由折叠），只是窗口与呈现深度不同。分开做=三份重复实现。用户实测过 Codex++ 的 token 统计插件（`BigPizzaV3/CodexPlusPlusScriptMarket` → `scripts/codex-daily-token-usage.js`），认可其排版与图表形式，要求高程度复刻。【用户裁决】

**技术选型**：一个数据核 + 三级披露（L1/L2/L3），而非三个独立功能或单一巨面板。理由：三级各自回答不同时间尺度的问题，信息密度天然分层；宠物侧保持轻（L1/L2），深度统计放 WebUI 主列面板（L3），不违「宠物=低打扰表达层」定位。

**三层功能区分**【用户裁决：迷你条/黑板=高频观察，大看板=低频长周期】：

| 级 | 时间尺度 | 回答的问题 | 载体 | 呈现 |
|---|---|---|---|---|
| L1 迷你条 | 此刻 | 现在节奏如何、今日烧到哪了 | 悬浮迷你条（**内容冻结**：不按模型；结构唯一增量=R6 的钻取按钮） | 悬停 0.5s 即得，0 次点击 |
| L2 小黑板 | 今天 | 刚干完的活什么交代、7 日走势一瞥 | 黑板浮层（加料） | 事件触发或 1 次点击，15s 临时 |
| L3 大看板 | 这段时间 | 用量规律：趋势/模型分布/任意回看 | WebUI 主列面板（新） | 2 次点击进入，常驻可回 |

**L2 与 L1 的包含关系（诚实边界）**：L2 的用量行覆盖 L1 全部口径信息（超集）；L1 的节奏表盘与状态计数行为 L1 专属，黑板不重复展示——黑板顶替迷你条期间（TTL 15s）二者暂不可见，关闭黑板即恢复。【用户裁决：黑板信息更全、二者互斥顶替】

**实现框架**：宿主一次聚合产出 `dashboard` 快照字段（当日五口径+模型 TopN+近 14 日趋势+当日小时桶），L1/L2/L3 共用；L3 任意日期回看走按需路由。

## R1 性能审计与增量缓存（性能地基）

**来源背景**：用户要求全面排查开销不经济点。v2.1 全链路性能审计（2026-09-11，代码级核实）：

| # | 位置 | 现状（已核实） | 开销量级 |
|---|---|---|---|
| P1 | 引擎每轮事件扫描 | 每会话每轮 **5 遍 O(M) 全扫**：`scanSession`、`buildDashboard` 内 `scanInfo`（与前者重复的第二遍，即 issue #4 引擎双扫描）、`events5mCount`、`foldUsage`、`estimateUserTokensByDay`（算全部日期只用今日值） | N 会话 × 5M 每 1.5s；长命会话 10 万+事件时每轮数十毫秒级浪费 |
| P2 | `/state` 每次请求的宠物 IO | `snapshotExtra` 内 `loadManifest`（fs 读 + JSON.parse）与 `listPets`（readdirSync 整个宠物目录 + 逐宠物读 manifest）**每 1.5s 执行**，宠物目录实际极少变化 | 每轮目录 IO；宠物越多越贵 |
| P3 | `/state` 序列化与传输 | `JSON.stringify` 全量快照（projects + dashboard + pets + voices + guard）每轮全量；客户端全量 parse + 全量校验 | 体积随宠物/项目数线性，多数轮次内容与上轮相同 |
| P4 | 客户端轮询节奏 | 页面不可见（`document.hidden`）时仍 1.5s 全速轮询 | 标题闪烁只需分钟级信号，全速属浪费 |

（已排除的伪热点：harness `snapshotEvents()` 内部有 `eventsSnapshot` memo，数组复制仅在事件增长后发生一次，非每轮复制。）

**技术选型与处置**：
- P1 → **按「末事件 seq 指纹」的每会话增量缓存**，而非降轮询频率（1.5s 是状态卡/警报实时性契约，不能动）。理由：事件流 append-only，末事件 seq 不变则折叠量必然不变，指纹判据可靠；缓存一次吃掉全部 5 遍。
- P2 → 宠物清单与 manifest 改 **mtime 指纹缓存**（目录 mtime + manifest mtime 任一变化才重扫），宠物导入/删除天然触发目录 mtime 变化。
- P3 → 趋势/聚合随 R3 节流收敛；`/state` 增 **seq 短路**：客户端带 `?since=<seq>`，宿主 seq 未变时返回 304 式空体（省 stringify+传输+parse）。
- P4 → 页面不可见时轮询降频至 5s，`visibilitychange` 可见即恢复 1.5s；警报为分钟级语义（approvalFlickerMin 默认 5 分钟），5s 降频不影响。

**实现框架**：把每会话聚合拆两类——
- **事件折叠量**（可缓存）：`foldUsage` 产物（byDay/byHour/byRoute/byDayRoute 交叉账/请求计数）、用户输入估算（全日 map，R3 区间聚合消费）、工具调用按日统计、错误数、turn 数、`scanSession` 的状态机结论与 lines——指纹（末事件 seq）未变直接复用缓存；
- **时间派生量**（每轮重算）：pace 档位、审批等待分钟、黑板行、年龄标注——从缓存锚点时间戳推导，不重扫事件。
- 正确性验证沿用 v2.1 审计法：与 harness 官方 `tokenUsage` totals 按会话抽样对账（含子代理会话）。

## R2 模型/供应商分布（F05，一期欠账清偿）

**来源背景**：F05 为一期正式条目，v2.1 时因事件无 model 字段只立了空桶（`usage.models: {}`）。rc.2 已验证数据源存在：`assistant/message` 事件带 `message.source.{provider, model}`（真实日志落锤）【已验证】。用户裁定其为最高优先级欠账。【用户裁决】

**技术选型**：在 `foldUsage` 的（turn,step）替换槽**结算时**按最终样本路由记账，而非事后按消息归因。理由：五口径的替换语义（同 turn/step 取最新样本）必须与路由归因在同一次结算生效，否则替换丢弃的样本会污染路由账本。

**实现框架**：
- `foldUsage(evts)` 返回值扩展 `byRoute: { [provider/model]: {inputTokens, outputTokens, cacheReadTokens, cacheWriteTokens, requestCount} }`；route 缺失（空串）归「未知」桶。
- 快照下发 `usage.models`：当日 Top6（`{provider, model, requestTotal, cacheRead, outputTokens}`）。
- 呈现：L2 一行 Top3、L3 模型分布区全量（见 R4/R5）；L1 不按模型【用户裁决】。
- 对账：与官方 totals 的路由维度抽样比对（projcache 含 provider 维度）。

## R3 趋势数据窗口（14 日常驻 + 当日小时桶 + 按需回看）

**来源背景**：F10 sparkline、F40 周/上期对比、以及用户裁决的回看选项卡（近 5 小时/近 7 天/近 30 天 + 自定义范围最长 1 个月）。【用户裁决】

**技术选型**：
- 快照常驻**近 14 日日粒度数组 + 当日 24 小时桶**（合计 <2.5KB），更早历史走 `webServer` 按需路由。理由：本周/上周对比、7 日/30 天常见视图里 14 日内免请求；30 天与自定义范围是低频操作，按需拉取+客户端短缓存即可，不撑大 1.5s 快照。
- **计算节奏【用户裁决：整点锚定，不做秒级滚动】**：小时桶与 5h 窗口按**整点对齐**（窗口=最近 5 个完整整点桶，不含进行中的小时）；趋势数组仅在 (a) 任一会话 usage 指纹变化 (b) 跨整点/跨日 两个条件下重算，每 1.5s 轮询直接复用缓存值。理由：秒级滚动重算不经济，整点语义对观察窗口足够；事件驱动的变化由 R1 指纹自然触发。
- 「近 5 小时」是**观察窗口**（非订阅计费窗口）——F11 存档不翻案。
- 粒度映射：5h 视图 x 轴=小时桶；7d/30d/自定义=x 轴=日。

**实现框架**：
- 快照 `dashboard.trend.days: [{key, dayTotal, requestTotal, cacheRead, outputTokens, hitPct, requestCount}]`（近 14 日）+ `dashboard.trend.hours: [24 桶]`（当日）。
- 按需路由 `/dashboard/range?from&to`（日粒度，跨度 ≤31 天校验）：返回逐日数组 + **区间聚合**（五口径合计、模型 byRoute TopN、工具 Top5）——L3 的模型分布/工具区随视图联动，非仅当日数据。
- R1 增量缓存使 byDay 聚合免重扫；小时桶由当日事件时间戳分桶。

## R4 L2 小黑板加料

**来源背景**：用户定位——黑板偏向高频观察且应比迷你条「显示的全一点」；黑板用量信息为迷你条超集（边界口径见 R0），二者互斥顶替。【用户裁决】

**技术选型**：黑板复用现有容器加三行，而非新组件。理由：黑板生命周期（📖 限时入口/关宠分发/15s 自动/✕/点外/ESC）与锚定规则已定型，加行是最低成本扩展；不产生第二浮层。

**实现框架**：现有行之后追加——
1. **7 日 sparkline 行**：静态 SVG/div 柱（Codex++ 趋势图的微缩形态），无任何交互，灰字「7日」；
2. **模型 Top3 行**：`模型A 数值 · 模型B 数值 · 模型C 数值`，超 3 个折「等N」；
3. **入口行**「查看完整看板 →」：右对齐链接样式，行为唯一=打开 L3 并关黑板。
- 黑板出现即顶替迷你条（互斥，见 R0）；宽度维持 310px 换行排版。

## R5 L3 大看板（复刻 Codex++ 排版）

**来源背景**：用户实测认可 Codex++ `codex-daily-token-usage` 面板排版（hero 大数字/指标网格/渐变趋势图/模型分布进度条/2×2 工具格/日期导航/分区卡片），要求高程度复刻其内容与图表形式。【用户裁决】

**技术选型**：
- 挂载 `main` keyed 面板（自有键 `foxbell-dashboard`）而非 `rightbar`（single 位已被官方右栏占据，替换=遮蔽官方 UI）或宠物侧浮层（深度统计需要大画布、滚动、可停留）。**已对 rc.2 slot 目录验证**：`main` 保留键 `conversation` 之外开放，`sidebar.panellist` 为 additive 空位。
- **不注册侧栏图标**（默认）：用户不希望增加一级入口，机制扩展在插件内部解决；设置卡提供「侧栏看板入口」开关（默认关）满足「除非设置里写明触发位置」。【用户裁决】
- 不复刻：价格估算与价格面板（F04 存档）、推理 token 单列（F03 存档）、canvas 之外无新增依赖。

**实现框架**——面板分区（自上而下，配色全部走 dsh 主题 CSS 变量）：
1. 头部：标题 + 视图选项卡【近 5 小时 | 近 7 天 | 近 30 天】+ 自定义日期范围（≤31 天）+「复制文本」「导出图片」按钮；
2. hero：区间累计 Token 大数字（四桶和，随视图联动）；
3. 五口径网格（label-value 两列，名词与 L1 一致）：用户输入(估，含子代理)/产出/请求输入(全文累计)/缓存命中/命中率，附请求次数、数据截止时间（快照时间，非今日视图也成立）；
4. 趋势图：SVG（Codex++ 形态：三横向网格线、蓝→紫渐变折线 #3BA7FF→#8D6BFF、同色渐变面积、数据点圆圈、峰值标注、hover tooltip、轴标签），x 轴粒度随视图（小时/日）；趋势区头部右侧「本周命中率 X%（上周 Y%，±Z.pt）」（F40）；
5. 按模型分布：模型名（粗体截断）+ 请求输入数值 + 通栏 5px 圆角进度条（按 max 占比，下限 4%），≤6 行，title 显精确值；
6. 工具调用：2×2 指标格（调用总数/平均耗时/Top 工具次数/Top 工具总耗时）+ Top5 工具列表；
7. 底部：口径说明「纯 token · 含子代理 · 本地聚合」+ 数据新鲜度。

## R6 入口与钻取链

**来源背景**：用户提出——大看板怎么触发符合定位且方便？同一功能块多入口会不会困扰？迷你条点击「查看详情」、黑板把迷你条盖住会不会更好？【用户裁决方向】

**技术选型**：**单一方向钻取链 + 一个常驻辅入口**，而非多平行入口。理由：所有入口都朝「越点越深」同一方向（L1→L2→L3），不产生「两个入口到两个不同地方」的困扰；黑板入口只在黑板可见时存在（事件后限时），右键是黑板未开时的常驻直达，二者到达同一面板同一状态。

**实现框架**：
- **主链**：迷你条尾部「详情 »」按钮（迷你条**唯一**可点元素——容器整体仍 pointer-events:none，仅该按钮局部开启 auto，区域外点击照旧穿透）→ 打开黑板（顶替迷你条，见 R0）→ 黑板「查看完整看板 →」→ L3 主列面板；
- **辅入口**：宠物右键菜单新子项「用量看板」直达 L3（6.6 允许的接入正道）；
- **可选入口**：设置卡「侧栏看板入口」开关（默认关，开启后注册 `sidebar.panellist` 图标）；
- 宠物菜单→切主列面板的注入面（候选 `ctx.layout`/面板动作）为 plan 阶段验证项；退化方案=该菜单项点亮侧栏开关或仅黑板链可达。
- 交互铁律增补：迷你条从「纯只读」修订为「单一钻取入口」（用户裁决推翻自己此前铁律，其余铁律——拖拽无命令/单击每目标单行为/本体无操作按钮——不变）。

## R7 看板音效（MAM 机制 + 默认音效）

**来源背景**：v2.1 偏差 D-4——manifest 语音组只认 MAM 四组（`general/approval/done/error`），阈值/里程碑警报无语音可用，只能 TTS/静默。用户裁定：语音机制采用 MAM 的机制，四组配齐才生效，配不齐用看板默认音效（从 MAM 拿几个）。【用户裁决】

**技术选型**：维持 MAM 四组体系不扩第五组（与「采用 MAM 机制」一致，避免 D-3 已论证的「全有或全无」翻转向题）；看板警报音效独立于宠物语音组成环。理由：宠物包生态按 MAM 四组出素材是既成事实，扩组要求包生态迁移，成本大于收益。

**实现框架**：
- manifest `VOICE_GROUPS` 维持四组不动；宠物语音启用条件不变（四组全配，`judgeVoiceTier` 现状）；
- 看板警报（阈值/里程碑）音效链：宠物语音可用 → 播宠物 `general` 组音效；不可用 → 播**内置看板默认音效集**（2-3 个短音效轮换；音源裁定（plan 阶段）：MAM 二进制许可未核实，改用仓内脚本合成同风格 chime（`scripts/gen-alert-sounds.mjs`），许可洁净）；
- 清理 v2.1 遗留死路径：客户端 voices `GROUPS` 中 `'usage'` 组移除（manifest 永不承认，现状不可达）；**调用点同步改造**——警报播报处现行的 `playVoice('usage') → TTS → 静默` 三优先级链改为本条新链（宠物语音可用→`general` 组 / 否则→默认音效），移除组与改调用点必须同 commit，避免空转调用；
- 【默认裁定】TTS 开关维持现状（用于台词朗读），不参与看板音效链。

## R8 导出分享图片（模板 + 宠物形象 + 智能评语）

**来源背景**：用户对 Codex++ 分享按钮的延伸设计——套模板导出图片，底部带当前激活宠物形象，按已监控要素说针对性评论（预制模板），支持自定义导出评语。【用户裁决】

**技术选型**：客户端 canvas 绘制 + 预制评语模板池（纯规则匹配），不引入图表库/图片服务。理由：版式元素（数字/柱线/立绘/文字）全部是 canvas 原生可绘；评语由已监控要素规则匹配即可达成「有针对性」，无需 LLM。

**实现框架**：
- **版式模板**（固定）：标题（视图与日期范围）→ hero 数字 → 趋势 mini 图（当前视图数据）→ 五口径摘要行 → 模型 Top3 行 → 底部当前激活宠物立绘 + 气泡评语；
- **宠物形象【用户裁决：随机 + 自选】**：立绘 = 当前激活宠物 spritesheet 的**单帧 `drawImage` 绘制**（canvas 原生，无 DOM 依赖）；姿态选择——默认**随机动作**（从当前宠物动画变体清单随机取一个变体的代表帧，导出时抽取），设置卡提供「导出姿态」下拉（选项=当前宠物的变体清单 +「随机」），切换宠物后回退「随机」（变体清单随宠物走，不做跨宠物持久化）；
- **智能评语**：从预制模板池按要素优先级匹配一条——候选要素：区间总量档位（高/中/低）、趋势方向（升/降/平）、命中率档位（高/低）、模型形态（单模型/多模型）、当日节奏（高强度/摸鱼）；池初始 8-12 条，zh/en 双语；
- **自定义评语**：设置卡「导出评语」文本框，支持占位符（如 `{range}` `{tokens}` `{hitPct}` `{models}`），留空走预制池；
- 导出动作：`canvas.toBlob` → 下载 PNG；「复制文本」为纯文本摘要（同数据、无绘图）。
