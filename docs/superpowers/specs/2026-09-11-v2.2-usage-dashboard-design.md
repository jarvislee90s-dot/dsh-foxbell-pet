- 状态：待用户审阅

- 定位：本文档是二期「用量看板」板块的功能设计——把设计稿 §9 中需求重叠度高的三件事（F05 模型分布、F10/F40 趋势、F38 周报）收敛为**一个数据核 + 三级披露**，并清偿一期欠账。代码级细节留给 plan 文档。

## 1. 背景与目标

- v2.1.0 已交付五口径迷你条/黑板/阈值警报，但趋势、模型分布、周期复盘全部空缺；`usage.models` 是空桶、MiniBar L91 与 Board L34 留有二期挂载注释位。
- 用户实测过 Codex++ 的 token 统计插件，认可其排版：周曲线图 + 缓存命中 + 按模型分布。
- 本期目标：**一个板块（用量看板）、三级披露（L1 迷你条 → L2 黑板 → L3 大看板）**，数据一次聚合、按披露深度分级呈现。

## 2. 调研综述（2026-09-11，本设计的三个事实基础）

### 2.1 Codex++ 插件解剖（复刻母本）

- 仓库：`BigPizzaV3/CodexPlusPlusScriptMarket` → `scripts/codex-daily-token-usage.js`（4588 行，v0.1.x；宿主工具 `BigPizzaV3/CodexPlusPlus` 为 Tauri 应用，经注入脚本挂进 Codex 桌面端）。同仓另有 `codex-token-usage.js`（消息旁 badge，非本期母本）。
- 面板结构（自上而下）：
  1. 头部：触发按钮 + 价格开关 + **日期导航（‹ 日期选择器 ›，任意回看）**；
  2. 摘要区：**「累计 Token」hero 大数字**；
  3. 指标网格：label-value 两列（输入/输出/缓存输入/推理/请求次数/最近更新）；
  4. **近 5 日趋势 SVG**（viewBox 300×82）：三条横向网格线、蓝→紫渐变折线（#3BA7FF→#8D6BFF，stroke 3 圆角）、同色渐变面积（透明度 0.22→0.02）、数据点圆圈（选中 4.2px/普通 3.1px，白底渐变描边）、峰值标注、pointer tooltip（精确值+请求次数）、底部日期标签行；
  5. **按 Model 分布**：模型名（粗体截断）+ 数值 + 通栏 5px 圆角进度条（按 max 占比，下限 4%），最多 6 行；
  6. 工具调用：**2×2 小指标格**（可识别请求/调用率/调用密度/关联用量）+ 工具列表；
  7. 底部：状态灯 + **分享按钮（canvas 绘图导出图片）**；
  8. 各分区为圆角卡片（10px 圆角、1px 边框、次级背景、内间距 ~11px），颜色全部走宿主主题 CSS 变量。
- **复刻清单**：hero、指标网格（映射为我们的五口径）、近 7 日渐变趋势图（含 tooltip/峰值）、模型分布进度条行、2×2 工具指标格、日期导航、分区卡片排版、主题变量化配色。
- **不复刻**：价格估算与价格设置面板（F04 已存档，维持纯 token 口径）、推理 token 单列（F03 已存档）、5 日窗口（我们取 7 日，与周对齐）、canvas 图片分享（本期只做复制文本，见 §8）。

### 2.2 dsh 插件协议：大看板的官方挂载道（rc.2 验证）

- `main` slot：**keyed、scope root**——保留键 `conversation` 承载会话，**其他键开放**；插件以自有键（`foxbell-dashboard`）注册即得主列面板（宽高/滚动/主题全原生）。
- `sidebar.panellist`：**list、additive（occupants 为空、replaceRisk none）**——注册同 id 的左侧栏全局图标，点击切换主列面板，官方导航结构。
- `rightbar` 为 single 且被官方右栏占据（replaceRisk: shadows-shipped-ui），**不走**。
- 宠物侧菜单 → 切换主列面板的注入面（候选 `ctx.layout` / `usePanelInfo` 动作）待 plan 阶段验证；侧栏图标点击本身是原生行为，不依赖此验证。

## 3. 需求归纳：一个板块、三级披露

**同源关系**：F05（按模型分布）、F10/F40（趋势/周对比）、F38（周报）读的是同一份聚合数据（会话事件的 usage 按日按路由折叠），只是窗口和呈现深度不同——分开做=三份重复实现（继承 brainstorm §5 的同族归并逻辑）。

| 级 | 载体 | 内容 | 触发 | 新增常驻 UI |
|---|---|---|---|---|
| L1 | 悬浮迷你条（现状冻结） | 今日请求输入/命中率/产出/你的输入(估)/状态行/本会话——**不按模型** | 悬停 0.5s / 右键「今日用量」 | 无 |
| L2 | 小黑板（加料） | 现有总结行 + **7 日 sparkline 行** + **模型 Top3 行** + 「查看完整看板 →」入口行 | 📖 限时入口 / 右键「查看最近总结」 / 关宠分发（现状） | 无（复用黑板容器） |
| L3 | **大看板（新）**：`main` 主列面板，复刻 Codex++ 排版 | hero + 五口径网格 + 7 日趋势图 + 模型分布 + 工具调用 + 日期回看（任意日） | **侧栏图标（原生）** / **宠物右键「用量看板」** / 黑板入口行跳转 | 侧栏一个图标（WebUI 原生导航结构，宠物本体零变化） |

**周报的处理（用户裁决：不单独做）**：F38/F40 融入 L3——日期导航切到上周即得周报视图；趋势区附「本周命中率 X%（上周 Y%，±Z.pt）」一行。黑板周一自动弹方案**取消**，无新增自动打扰。

## 4. 形态设计

### 4.1 L1 迷你条（不动）

现状六行结构、尺寸、纯只读铁律全部保持。模型与趋势信息**不进 L1**（用户裁决：悬浮要简约、只看总数）。

### 4.2 L2 黑板加料

- 在现有行之后追加：① **7 日 sparkline 行**（Codex++ 趋势图的微缩版：纯 div 柱或 SVG，静态无交互，灰字「7日」）；② **模型 Top3 行**（`模型名 数值 · 模型名 数值 · 模型名 数值` 截断拼一行，超 3 个折「等N」）；③ **入口行**「查看完整看板 →」（右对齐链接样式，点击打开 L3）。
- 黑板宽度维持 310px 换行排版；ttl/关闭四路不变；锚定跟随见 §7。
- 入口行是黑板（本就可交互浮层）内的一个新目标，行为唯一=打开 L3；在 6.6 矩阵补一行（§6）。

### 4.3 L3 大看板（复刻 Codex++ 排版）

分区自上而下（对齐 §2.1 复刻清单，主题变量化适配 dsh 明暗主题）：

1. **头部**：标题「用量看板」+ 日期导航（‹ 日期选择器 ›，默认今日）+「复制文本」按钮。
2. **hero**：「今日累计 Token」大数字（四桶和，与 L1「今日」同口径；非今日时随日期联动）。
3. **五口径网格**（label-value 两列，沿用五口径名词）：用户输入(估，含子代理) / 产出 / 请求输入（全文累计）/ 缓存命中 / 命中率；附请求次数、最近更新。
4. **近 7 日趋势**：SVG 300×82 三网格线 + 蓝紫渐变折线/面积 + 数据点 + 峰值标注 + hover tooltip + 日期标签；数值口径=日四桶和；数据点 tooltip 附命中率。
5. **按模型分布**：模型行（名称粗体截断 + 请求输入数值 + 通栏 5px 圆角进度条），最多 6 行，按当日请求输入占比；行 title 显示精确值。
6. **工具调用**：2×2 指标格（调用总数 / 平均耗时 / Top 工具次数 / Top 工具耗时）+ Top5 工具列表（名称+次数+总耗时）。
7. **底部**：状态行（数据口径说明「纯 token · 含子代理 · 本地聚合」）。
8. **周对比**（F40）：趋势区头部右侧「本周命中率 X%（上周 Y%）」。

不进 L3 的：价格（F04 存档）、推理单列（F03 存档）、活动流（F34 存档）。

## 5. 数据与性能设计

### 5.1 增量缓存（issue #4 技术债#1，本期地基）

- 每会话缓存拆两类：**事件折叠量**（usage byDay/byRoute、工具耗时、错误数、turn 数——只随事件变化，以「末事件 seq 指纹」判缓存命中，未变则复用）与**时间派生量**（pace 档位、审批等待分钟、黑板行——每轮从缓存锚点时间重算，不重扫事件）。
- 7/14 日与模型聚合从缓存的 per-session byDay/byRoute 汇总，全量重扫仅在指纹变化时发生。
- 正确性对账：沿用 v2.1 审计方法，与 harness 官方 `tokenUsage` totals 按会话抽样比对（含子代理会话）。

### 5.2 foldUsage 扩展路由维度（F05）

- 读取 `assistant/message.data.message.source.{provider,model}`，在（turn,step）替换槽**结算时**按最终样本的路由记账（与五口径同一次结算，不破坏替换语义）。
- 下发 `usage.models: [{provider, model, requestTotal, cacheRead, outputTokens}]`（今日，Top6 截断）；`byRoute` 进缓存供任意日聚合。
- route 缺失（provider/model 空串）归「未知」桶；显示名 `provider/model` 截断。

### 5.3 数据通道

- `/state` 快照新增（约 2KB 内）：`dashboard.trend`（近 14 日数组：`{key, dayTotal, requestTotal, cacheRead, outputTokens, hitPct, requestCount}`；requestCount=当日结算的请求样本数，foldUsage 顺带计数）+ `dashboard.usage.models`（Top6）。L1/L2 与 L3 默认视图全部由快照驱动，无新增轮询。
- **任意日回看**：`webServer.register` 增按需路由（如 `/dashboard/day?key=YYYY-MM-DD`）返回该日全量（五口径+模型全量+工具 Top5）；L3 切日期时拉取，结果客户端短缓存。
- 周报视图=「上周日期范围」的按需拉取聚合（14 日内的本周/上周直接来自快照，更早走按需路由）。

## 6. 交互一致性（对 brainstorm spec 6.6 的增补）

- **铁律不变**：迷你条纯只读/pointer-events:none（L1 不加任何入口）；拖拽无命令；单击每目标单行为；宠物本体无操作按钮。
- 第二层矩阵**新增三行**：右键菜单项「用量看板」→切 L3；黑板「查看完整看板→」→切 L3 并关黑板；侧栏图标→切 L3（WebUI 原生，非宠物交互）。
- **关门声明维护**：本期未启用任何已关门通道；长悬停深读档、拖放导入、键盘快捷键三个预留接口继续闲置（L2 已直接承载趋势摘要，长悬停扩展档本期无占用必要）。
- 新增常驻 UI 清点：侧栏图标一枚（WebUI 原生导航位，非宠物侧）；宠物本体与既有浮层零新增。
