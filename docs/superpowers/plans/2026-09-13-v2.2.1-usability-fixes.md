## 背景（用户报告）

1. 本地源码版 harness 新建/继续会话必报 `Cannot find module … native/system/packages/darwin-arm64/bin/system.node`（flock）——会话完全不可用。
2. 报错时宠物播报两条语音且同时重叠（多客户端并发各播一次）。
3. 导出图片四处不满意：①自定义评语不该放设置里，应在看板头部直达；②评语气泡压住宠物立绘；③导出图里模型名被截断（DeepSeek-V…）；④卡片要素与 Codex++ 导出图差距大——要竖排版、按其复刻（金额除外）、最下方是评论气泡+宠物，像正常聊天卡片。
4. 悬浮条鼠标离开宠物即消失，「详情 »」永远点不到。

## 工作流 B：悬浮条 hover 桥接

根因：悬停进出事件挂在精灵方块（Pet.tsx sprite），悬浮条是兄弟节点且右侧留 12px 空隙；鼠标离开精灵（含穿隙）立即 `setMiniMode(null)` 卸载悬浮条。此前 E2E 用 Playwright 瞬移式 click 掩盖了该 bug（真人连续移动必现）。

- 精灵 `onPointerLeave`（hover 模式）改为启动 **200ms 宽限定时器** 而非直接卸载；
- `dyn-pet-mini-wrap` 加 `onPointerEnter` 取消宽限定时器（指针抵达悬浮条即保持）；精灵 `onPointerEnter` 同样先取消；
- 卸载清理定时器；manual 模式行为不变；
- 回归验证：Playwright `page.mouse.move(target, { steps: 20 })` 模拟真人连续移动，断言「悬停 → 分段移动到详情 → 点击 → 黑板打开」。

## 九追加轮（用户问：导出图宠物为什么变小）

- 根因：`petH = min(380, H - y - 96)`——上方分区（指标行数/模型行数）越多 y 越大，立绘高度被挤得越小（4 模型时实测 ~180px）。与主界面「宠物大小」设置无关（导出是独立 canvas，尺寸从未参与）。
- 修复（T6）：立绘固定 360px 高，空间不足时**加高画布**（H = y + PET_H + 96）而非缩小立绘。真机导出核对：T6-export-bigpet.png（立绘恢复满尺寸，4 模型行 + 底部聊天区完整）。
